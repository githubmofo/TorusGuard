# TorusGuard Security Architecture & Privacy Policy

## 1. Threat Model & Trust Boundaries

TorusGuard operates under a strict **Zero-Trust Local Execution Threat Model**:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Local Trust Boundary                            │
│                                                                        │
│   ┌───────────────────────┐              ┌─────────────────────────┐   │
│   │   Target Codebase     │ ───────────► │  TorusGuard Engine      │   │
│   │   (Sensitive Source)  │              │  (Local Parser & Rules) │   │
│   └───────────────────────┘              └───────────┬─────────────┘   │
│                                                      │                 │
│                                                      ▼                 │
│                                          ┌─────────────────────────┐   │
│                                          │  Redacted Local Reports │   │
│                                          │  (.torusguard/runs/...) │   │
│                                          └─────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
                                 ✖ (NO NETWORK EGRESS)
                    ┌────────────────────────────┐
                    │ External Internet / Cloud  │
                    └────────────────────────────┘
```

### 1.1. Zero Network Egress Guarantee
TorusGuard never transmits source code, AST trees, findings, environment secrets, or metadata to external servers, cloud AI backends, or telemetry endpoints. All evaluation logic runs locally within the developer workspace.

### 1.2. Automated Sensitive Data Masking (`core/formatter.py`)
To prevent accidental credential leaks into shared audit reports or issue tracking tickets, TorusGuard applies real-time redaction to raw code evidence snippets:
- **API Secret Keys:** `sk_live_[0-9a-zA-Z]{24,}` ──► `[REDACTED_API_KEY]`
- **GitHub Personal Access Tokens:** `ghp_[0-9a-zA-Z]{36}` ──► `[REDACTED_GITHUB_TOKEN]`
- **JSON Web Tokens (JWTs):** `eyJ[a-zA-Z0-9_-]+\.eyJ[a-zA-Z0-9_-]+\.[a-zA-Z0-9_-]+` ──► `[REDACTED_JWT_TOKEN]`
- **Passwords & Passphrases:** Hardcoded password assignments ──► `password = "[REDACTED_SECRET]"`

## 2. Integrity & Cryptographic Provenance

Every candidate finding generated by TorusGuard is cryptographically bound to its source evidence:
1. **Raw Evidence Hashing:** A SHA-256 hash of the exact code snippet is computed at the moment of detection ($H_{raw}$).
2. **Provenance Decision Trail:** Records the exact module, triggering pattern, and confidence deduction path.
3. **Retest Assertion:** Post-remediation verification computes a new SHA-256 hash ($H_{post}$) to mathematically assert that the vulnerable code block was modified.

## 3. Runtime Safety Gates & Target Authorization (`safety_gate.py`)

When runtime validation probes are executed (`/torusguard verify`, `web-validate`, `exploit-check`):
1. **Target Authorization Gate:** Enforces explicit target ownership and host allowlisting via `.torusguard/config/scope.json`. Out-of-scope targets or expired TTLs halt immediately.
2. **Three-Tier Safety Review Policy:**
   - **Auto-Allowed:** Non-sensitive read-only `GET`, `HEAD`, `OPTIONS` requests.
   - **Approval Required:** Sensitive authentication endpoints or state-changing verbs (`POST`, `PUT`) require explicit operator sign-off.
   - **Manual Only / Blocked:** Destructive operations (`DELETE`, `DROP`) are permanently blocked from automated agent dispatch.
3. **Automated Payload Redaction:** All captured HTTP cookies, Bearer tokens, and request payloads are sanitized before persisting to `requests.json` and `responses.json`.

---

## 4. Governed Remediation & The Ponytail Protocol

To prevent AI coding assistants from introducing catastrophic code modifications:
- Hard line churn bounds: additions $\le 35$ lines, deletions $\le 25$ lines per bundle.
- Full-file rewrites strictly prohibited.
- Pre-apply rollback snapshots saved to `pre_apply/<file>.bak` before disk modification.
