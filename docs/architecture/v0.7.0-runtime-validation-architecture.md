**Status:** Approved

## 1. Architectural Motivation & Intent

While TorusGuard v0.6.x mastered governed static remediation, minimal patch bounds, and targeted rechecks, static analysis inherently possesses limits:
- Middleware or reverse proxy barriers may guard seemingly unprotected code in production.
- Theoretical IDOR findings may be defended by implicit database row-level security or custom ORM session filters.
- AI coding agents lack proof whether a flagged flaw can be exploited in a running deployment.

TorusGuard **v0.7.0** introduces an **Authorized Runtime Validation and Bounded Exploitability Confirmation Layer** that operates safely alongside governed remediation.

```text
+---------------------------------------------------------------------------------------+
|                               TorusGuard v0.7.0 Architecture                          |
+---------------------------------------------------------------------------------------+
|  [0. Legal & Scope Gate]  ->  TargetScope + AuthorizationRecord (scope.json)           |
|                                         |                                             |
|  [1. Profiler Role]       ->  Stack Profiling + AST Route Extraction                  |
|                                         |                                             |
|  [2. Static Audit]        ->  Stable Fingerprints + Root-Cause Clustering (v6 base)   |
|                                         |                                             |
|  [3. Validator Role]      ->  WebValidator + SafetyGate + ExploitChecker              |
|                               - Auth Bypass Probe                                     |
|                               - Tenant Isolation / IDOR Probe                         |
|                               - Header Trust Injection Probe                          |
|                               - Exposed Debug Endpoint Probe                          |
|                                         |                                             |
|  [4. Remediator Role]     ->  Remediation Bundles Enriched with Exploitability Status |
|                                         |                                             |
|  [5. Reviewer Role]       ->  Evidence Sign-Off + Multi-Analysis SARIF + Replay Trace  |
+---------------------------------------------------------------------------------------+
```

## 2. Core Subsystems

### 2.1. Authorization & Scope Manager (`core/authorization.py`)
No network request or browser interaction is dispatched without valid target consent:
- `TargetScope`: Defines authorized hosts, whitelisted path prefixes, forbidden sensitive paths, expiration timestamps, and request budgets.
- `AuthorizationManager`: Validates every outbound URI against the scope and raises `AuthorizationError` if violated.
- Emits `authorization.md` and `scope.json` into the run folder.

### 2.2. Safety Review Gates (`core/safety_gate.py`)
All proposed runtime actions are evaluated before dispatch:
- **`Auto-Allowed`**: Read-only `GET` to non-sensitive endpoints.
- **`Approval Required`**: State-changing methods (`POST`, `PUT`, `DELETE`) or sensitive contexts (`auth`, `login`, `tenant`, `upload`).
- **`Manual Only`**: Critical destructive operations (`/admin/delete`, `/system/shutdown`).
- Emits `safety-decisions.json`.

### 2.3. Runtime Evidence & Secret Redaction (`core/runtime_evidence.py`)
- Standardizes interaction logs: `requests.json` and `responses.json`.
- `RedactionEngine`: Automatically redacts Bearer JWTs, Basic Auth credentials, API keys, and sensitive payload fields before persistence.

### 2.4. Bounded Exploitability Engine (`core/exploit_checker.py`)
Safe, bounded checks designed to stop on first sufficient proof:
- **Formal Status Classifications:**
  - `Runtime Confirmed`: Direct evidence with expected sensitive marker.
  - `Runtime Likely`: Strong behavioral signal without full payload leak.
  - `Needs Manual Review`: Ambiguous or complex response requiring human verification.
  - `Not Reproducible in Scope`: Mitigated by active gateway or middleware barrier.
  - `Blocked by Environment / Controls`: Halted by Safety Gate or authorization bounds.

### 2.5. Multi-Agent Governance & Role Separation (`core/agent_roles.py`)
Enforces strict boundaries between AI agent roles:
1. **Profiler:** Static reconnaissance only.
2. **Validator:** Active runtime verification only.
3. **Remediator:** Code patch formulation only.
4. **Reviewer:** Evidence audit and governance sign-off.
- Emits `agent-handoffs.md` and `role-audit.json`.

### 2.6. Replayable Validation Traces (`core/replay_trace.py`)
- Emits `replay.json` and `replay.md` capturing deterministic action steps and expected response assertions for reproducibility.
- Re-executed via `ReplayManager.execute_replay()`.

### 2.7. Multi-Analysis SARIF v2.1.0 Hygiene (`core/sarif.py`)
- Supports partitioned uploads via `runs[].automationDetails.id` (`torusguard/runtime/` vs `torusguard/static/`), preventing GitHub Code Scanning collision.
