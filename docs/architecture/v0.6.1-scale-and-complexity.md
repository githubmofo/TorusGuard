## 2. Key Architecture Pillars

### 2.1. Monorepo & Deep-Directory Invariance
- Finding fingerprinting maintains absolute path stability regardless of repository nesting depth (tested up to 8 levels: `services/core/v1/subsystems/analytics/processors/workers/handler.py`).
- Relative normalizers map code regions consistently across monorepo workspace roots.

### 2.2. Generated File Suppression
Paths matching known compiler, bundle, or vendor artifacts are flagged and suppressed from cluttering security reviews:
- `migrations/` (ORM migration history)
- `node_modules/`, `vendor/` (Dependency vendor trees)
- `dist/`, `build/` (Frontend build artifacts)
- `*.min.js`, `*.min.css` (Minified production code)
- `*.pb.go`, `*_pb2.py` (Compiled Protobuf definitions)

### 2.3. Report Usability & Collapsing Thresholds
To ensure reports remain human-friendly and fit within LLM context windows during AI agent pairing:
- **Small-to-Medium Runs ($\le 25$ findings):** Standard detailed finding cards with full code snippets.
- **High-Density Runs ($> 25$ findings):** Top 15 critical/high-confidence findings are rendered in detail; the remainder are collapsed into structured, sortable Markdown tables grouped by root cause.

### 2.4. Cross-Boundary Patch Governance
- Patch governor enforces boundary restrictions: automated patches are restricted from spanning multiple separate microservices in a single diff to prevent cross-service regression risks.
