# TorusGuard Architectural Glossary & Taxonomy

## 1. Core Terminology

- **AI Coding Agent:** An LLM-powered development assistant (such as Cursor, Antigravity, Claude Code, Cline, Codex, or Gemini CLI) that generates, modifies, and tests application source code.
- **The Browser-Code Truth:** The fundamental architectural premise stating that any code, bundle, or asset sent to a web browser cannot be hidden from client inspection or modification.
- **Finding:** A discrete security observation generated by the detection engine, containing evidence, confidence scoring, provenance metadata, and remediation diffs.
- **Ponytail Protocol:** The least-invasive automated remediation standard requiring minimal line churn, zero unrelated file modifications, framework-native idioms, and verified rechecks.
- **Recheck (`/torusguard recheck`):** The automated differential re-audit process that verifies whether a modified codebase resolves a previously identified finding without introducing regressions.
- **Seeded Case:** A controlled, non-production test case containing a known vulnerability pattern injected into a benchmark repository to measure detection recall.

## 2. Taxonomy & Rule ID Prefixes

| Prefix | Domain | Description |
|---|---|---|
| `TG-AUTH-*` | Authentication & Authorization | RBAC, session management, header injection, mass assignment, IDOR |
| `TG-DB-*` | Database Security | Frontend DB queries, multi-tenant isolation, raw SQL concatenation |
| `TG-INPUT-*` | Input Validation | SSTI, unescaped template rendering, path traversal, unsafe uploads |
| `TG-SEC-*` | Secrets & Cryptography | Hardcoded tokens, tracked `.env` files, sensitive logging, weak hashing |
| `TG-PLATFORM-*`| Platform Hardening | Wildcard CORS, missing security headers, stack trace leakage |
| `TG-RATE-*` | Rate Limiting & Resource Management | Unbounded pagination, unthrottled authentication endpoints |
| `TG-SSRF-*` | Server-Side Request Forgery | Unvalidated outbound HTTP requests, cloud metadata access |
| `TG-WEBHOOK-*` | Webhook Security | Missing HMAC signatures, replay attack vulnerability, timestamp bounds |
| `TG-GQL-*` | GraphQL Security | Unbounded query depth/complexity, missing field-level authorization |
| `TG-WS-*` | WebSocket Security | Unauthenticated handshake, missing channel authorization, unbounded frames |
| `TG-SUPPLY-*` | Supply Chain Security | Vulnerable third-party dependencies, unpinned CI/CD actions |

## 3. Finding Lifecycle States

1. **`Detect`:** Initial pattern match on repository source code.
2. **`Classify`:** Assigns canonical Rule ID, CWE mapping, and initial severity.
3. **`Verify`:** Confirms AST reachability and evaluates mathematical confidence score.
4. **`Remediate`:** Generates Ponytail unified Git diffs.
5. **`Re-check`:** Re-audits post-fix source code.
6. **`Archive`:** Persists immutable run metadata and evidence hashes.

---

## 4. Retest Status Values

- **`Verified Fixed`:** Vulnerability pattern completely resolved; passes automated tests.
- **`Still Present`:** Flaw remains detectable in modified code.
- **`Partially Fixed`:** Vulnerability partially mitigated but residual risk remains.
- **`New Risk`:** Remediation patch introduced a secondary security vulnerability.
- **`Not Applied`:** Patch was generated but not committed to target repository.
- **`Not Recheckable`:** Verification requires live infrastructure or runtime testing outside static analysis scope.
