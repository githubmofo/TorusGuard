# TorusGuard Architectural Glossary & Taxonomy

## 1. Core Terminology

- **AI Coding Agent:** An LLM-powered development assistant (such as Cursor, Antigravity, Claude Code, Cline, Codex, or Gemini CLI) that generates, modifies, and tests application source code.
- **The Browser-Code Truth:** The fundamental architectural premise stating that any code, bundle, or asset sent to a web browser cannot be hidden from client inspection or modification.
- **Finding:** A discrete security observation generated by the detection engine, containing evidence, confidence scoring, provenance metadata, and remediation diffs.
- **Ponytail Protocol:** The least-invasive automated remediation standard requiring minimal line churn ($\le 35$ additions, $\le 25$ deletions per bundle), zero unrelated file modifications, framework-native idioms, and verified rechecks.
- **Living Security Report (`security_report.md`):** Root-level immutable ledger acting as the single source of truth across terminal CLI tools and AI agent chat sessions to eliminate hallucination.
- **Human Gate:** The mandatory operator confirmation boundary (`npx torusguard apply`) that displays syntax-highlighted diffs and captures pre-apply snapshots before touching disk.
- **Golden Fix Recipe:** A verified, minimal Before/After remediation diff distilled into `.torusguard/memory/patterns.json` for persistent intelligence.
- **Standardized 75-Column Terminal:** Visual width constraint strictly enforced across all TorusGuard CLI command outputs, handling Unicode emojis and ANSI stripping.
- **Recheck (`npx torusguard recheck` / `/torusguard recheck`):** The automated differential re-audit process that verifies whether a modified codebase resolves a previously identified finding without introducing regressions.
- **Seeded Case:** A controlled, non-production test case containing a known vulnerability pattern injected into a benchmark repository to measure detection recall.

## 3. Finding Lifecycle States

1. **`OPEN 🔴`:** Newly discovered vulnerability awaiting verification or patch formulation (`audit`).
2. **`VERIFIED 🟠`:** Confirmed finding with valid line coordinates and proof of reachability (`verify`).
3. **`CANDIDATE 🟡`:** Formulated surgical Ponytail patch bundle ready for operator review (`harden`).
4. **`APPLIED 🔵`:** Patch written to disk with pre-apply rollback snapshot saved (`apply`).
5. **`RESOLVED 🟢`:** Post-fix differential recheck asserted fix closure with zero regressions (`recheck`).
6. **`REGRESSED ❌`:** Recheck detected secondary vulnerability or incomplete fix.
7. **`FALSE POSITIVE ⚪`:** Finding discounted due to external gateway protection, mock fixture, or lack of evidence.
