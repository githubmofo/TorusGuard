## 2. Key Architectural Guarantees

### 2.1. GitHub Alert Deduplication via `partialFingerprints`
GitHub Code Scanning identifies recurring alerts across commit trees through `partialFingerprints`:
```json
"partialFingerprints": {
    "primaryLocationLineHash": "8a3b2c1d4e5f0123",
    "torusguard/v6/identity": "TG-FND-8a3b2c1d4e5f"
}
```
This prevents duplicate alerts from reopening when preceding lines in a file are edited.

### 2.2. Review Level Hierarchy
| Review Level | Trigger Conditions | Auto-Apply Permitted |
|---|---|:---:|
| **`Automatic`** | Low-risk general files, line churn $\le 35$ additions / $\le 25$ deletions. | ✅ Yes |
| **`Peer Review Recommended`** | Sensitive files (Auth, Tenancy, Crypto) with minimal churn ($\le 10$ lines). | ✅ Yes (with badge) |
| **`Mandatory Security Sign-Off`** | Sensitive files with non-trivial churn ($> 10$ lines) or multi-file diffs. | ❌ No (Blocked) |

### 2.3. Zero False-Positive Modern Negative Testing
To prevent false alarms in modern web frameworks, TorusGuard explicitly validates:
- Django 5.x async queries with explicit `tenant_id` parameters.
- FastAPI endpoints with `Annotated[User, Depends(get_verified_user)]`.
- SQLAlchemy 2.0 select statements with chained `.where(Model.tenant_id == ...)`.
- Next.js 14 Server Actions with `await auth()` barriers.
