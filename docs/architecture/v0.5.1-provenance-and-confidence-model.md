# TorusGuard v0.5.1 Provenance Tracking & Auditable Confidence Specification

## 🎯 Release Vision & Theme

**TorusGuard v0.5.1 Theme:** *“Normalize findings, prove provenance, and make confidence auditable.”*

v0.5.1 refines the v0.5.0 architecture to make every reported finding cryptographically traceable, mathematically scored for confidence, and provably verified post-remediation.

---

## 🏛️ 1. Canonical Finding Schema Architecture

Every security finding across all frameworks conforms to the single normalized schema defined in [`schemas/finding.schema.json`](../../schemas/finding.schema.json):

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Canonical Finding Object                           │
├─────────────────────────────────────────────────────────────────────────────┤
│  • finding_id           (Unique Instance ID, e.g. TG-FIND-2026-a1b2c3d4)   │
│  • rule_id              (Canonical Rule ID, e.g. TG-AUTH-007)               │
│  • title                (Human-readable summary)                            │
│  • category             (Normalized Taxonomy Category)                      │
│  • severity             (Level + Rubric Justification)                      │
│  • confidence           (0-100 Auditable Score + Classification Band)       │
│  • status               (Confirmed, High/Medium/Low, Needs Review, Fixed)  │
│  • affected_component   (File path, line range, symbol, module)             │
│  • provenance           (Discovery module, Trigger, Decision path)          │
│  • evidence             (Raw technical snippets + SHA-256 Checksums)        │
│  • reproduction_method  (Deterministic step-by-step reproduction)          │
│  • remediation          (Problem, risk, Framework Before/After Diffs)       │
│  • retest_result        (Retest timestamp, Method, Evidence Hash, Closure) │
│  • requirement_mapping  (OWASP ASVS, CWE, NIST SSDF)                        │
│  • timestamps           (Discovered, Verified, Remediated, Retested)        │
│  • notes                (Raw Facts Summary vs AI Interpretation)            │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 🔗 2. Provenance Chain

To prevent AI hallucination and ensure complete traceability, every finding records an explicit **Provenance Chain**:

```text
Discovery Module ──► Triggering Input ──► Decision Path ──► Verification Step
```

- **Discovery Module:** The exact rule or inspection pass that located the candidate pattern (e.g. `rules/authorization/TG-AUTH-007-missing-property-level-authorization.md`).
- **Triggering Input:** The precise syntax element, AST node, manifest entry, or route pattern that triggered detection.
- **Decision Path:** The ordered logical evaluation steps taken by the engine.
- **Verification Step:** The exact procedure used to validate or refute reachability.

## 📊 3. Auditable 0–100 Confidence Scoring Model

Confidence is evaluated using an objective 5-factor scoring rubric totaling **100 points**:

$$\text{Confidence Score} = \text{Evidence Quality (35)} + \text{Reproduction (25)} + \text{Confirmations (15)} + \text{Environmental Clarity (15)} + \text{Manual Review (10)}$$

### Scoring Rubric Breakdown

| Factor | Max Points | Evaluation Criteria |
|---|:---:|---|
| **Evidence Quality** | **35 pts** | **35:** Exact AST source match with reachable sink.<br>**25:** Regex/text match on configuration.<br>**15:** Indirect or delegated call signature. |
| **Reproduction Success** | **25 pts** | **25:** Deterministic reproduction in test fixture.<br>**15:** Partial reproduction with environmental assumptions.<br>**0:** Theoretical / non-reproducible. |
| **Independent Confirmations** | **15 pts** | **15:** Corroborated across multiple files/manifests.<br>**10:** Corroborated in single file.<br>**5:** Isolated uncorroborated snippet. |
| **Environmental Clarity** | **15 pts** | **15:** Standalone module with no unverified out-of-band layers.<br>**5:** Delegated to domain service layer or reverse proxy. |
| **Manual Review Status** | **10 pts** | **10:** Confirmed by human security engineer.<br>**5:** Awaiting human validation. |

### Classification Threshold Bands

| Score Range | Classification Band | Operational Meaning | Action |
|:---:|---|---|---|
| **90 – 100** | 🔒 **`Confirmed`** | Direct, indisputable proof of vulnerability | Remediate immediately |
| **70 – 89** | 🟢 **`High Confidence`** | Strong technical indicators present | Review and remediate |
| **50 – 69** | 🟡 **`Medium Confidence`** | Probable flaw; runtime confirmation recommended | Local verification |
| **< 50** | 🔍 **`Needs Review` / `Unconfirmed`** | Insufficient evidence or out-of-band delegation | Mandatory manual inspection |

## 📦 4. Raw Evidence Packaging & Integrity Hashing

TorusGuard v0.5.1 mandates strict cryptographic hashing of raw code evidence:
- **`sha256_checksum`:** Every raw code snippet has an immutable SHA-256 hash computed at extraction time (`hashlib.sha256(raw_snippet.encode('utf-8')).hexdigest()`).
- **Separation of Facts from Analysis:**
  - **Raw Facts Summary:** Objective statement of what the code does (e.g. *"Line 25 passes client-controlled id directly to Model.objects.get without user filter"*).
  - **AI Interpretation:** Analytical reasoning regarding exploitability and threat context.

## 🔁 5. Retest & Closure State Machine

A finding **cannot** be marked `Verified Fixed` without explicit retest evidence:

```text
Remediate Proposed ──► Patch Applied ──► Execute Retest (/torusguard recheck)
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
         [ Safe Pattern Verified ]                           [ Unsafe Pattern Remains ]
                    │                                                   │
                    ▼                                                   ▼
         Status: Verified Fixed                              Status: Open (Reverts)
         Evidence Hash Recorded                              Retest Failure Logged
```

## ⚖️ Standards Alignment

- **OWASP ASVS v4.0.3:** Maps findings to explicit verification requirements (e.g., `V4.1` Access Control, `V5.3` Output Encoding, `V14.4` Configuration).
- **NIST SP 800-218 (SSDF):** Fulfills `PW.5.1` (Validate inputs), `PW.6.1` (Configure securely), and `RV.1.1` (Verify fixes).
