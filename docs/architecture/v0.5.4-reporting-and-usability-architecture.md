# TorusGuard v0.5.4 Reporting & Usability Architecture Specification

## 🎯 Release Vision & Theme

**TorusGuard v0.5.4 Theme:** *“Make the findings readable, actionable, and ready for remediation.”*

v0.5.4 improves TorusGuard's reporting, usability, and ticket-readiness layer. It bridges the communication gap between product stakeholders, security engineers, and AI coding agents by structuring audit reports into a predictable 9-section narrative with clear business impact statements, prioritized remediation roadmaps, and copy-pasteable issue tracker payloads.

---

## 🏛️ 1. The 9-Section Standardized Report Flow

Every TorusGuard audit report renders through a deterministic 9-section architecture:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Report Header           (Project, Repository Ref, Engine Version, Date)  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. Executive Summary       (Stakeholder Overview, Metrics, Urgent Actions)   │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. Scope and Methodology   (Tested Scope, Boundary Conditions, Method)      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. Key Findings Table      (Compact 1-Glance Overview with Priorities)      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 5. Detailed Findings       (Business Context, Tech Mechanics, Diff, Ticket) │
├─────────────────────────────────────────────────────────────────────────────┤
│ 6. Remediation Priorities  (P0 Immediate / P1 Near-Term / P2 Backlog)       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 7. Retest & Verification   (Re-audit Method, Evidence Hash, Closure State)  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 8. Limitations             (Static Scope, Manual Review Cases, Boundaries)  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 9. Appendix & Models       (0-100 Confidence Rubric, Severity Definitions)  │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

## 🏢 2. Business Impact vs. Technical Mechanics Separation

Every detailed finding strictly separates context for different audiences:
- **🏢 Business Impact & Executive Context:** Non-technical, executive explanation of organizational risk (e.g. data breach liability, cross-tenant exposure, reputation harm).
- **⚙️ Technical Mechanics & Threat Context:** Technical explanation of source code vulnerabilities, data flows, and adversarial exploitation paths.

---

## 🚦 3. Remediation Prioritization (P0 / P1 / P2)

TorusGuard v0.5.4 automatically classifies findings into actionable triage tiers:
- **🚨 Immediate Priority (P0 — Pre-Deployment Blockers):** Remote Code Execution, unauthenticated SQL injection, hardcoded secrets, complete auth bypasses.
- **🟠 Near-Term Priority (P1 — Current Sprint Patch Cycle):** Object-level authorization bypass (IDOR), SSRF, XSS, multi-tenant data leakage.
- **🟡 Backlog / Hardening (P2 — Defense-in-Depth):** Rate limits, session cookie hardening, missing security headers.

---

## 🔒 4. Sensitive Data Masking Pipeline

TorusGuard automatically sanitizes evidence snippets to prevent credential leakage in audit reports:
- Stripe API keys (`sk_live_...` -> `sk_live_***REDACTED***`)
- GitHub Personal Access Tokens (`ghp_...` -> `ghp_***REDACTED***`)
- JWT Bearer Tokens (`Bearer eyJ...` -> `Bearer ***REDACTED_JWT***`)
- Generic password / secret variable assignments (`PASSWORD = '...'` -> `PASSWORD = '***REDACTED***'`)

---

## 🎫 5. Ticket-Ready Issue Tracker Payloads

Every finding includes a pre-formatted, expandable `<details>` section containing ready-to-copy Markdown for GitHub Issues, Jira, or Linear.
