# Release v0.5.5 — Folder-per-Run & Ponytail Integration

**Date:** 2026-08-27  
**Tag:** `v0.5.5`  

## 🎯 Release Goal
TorusGuard v0.5.5 introduces a streamlined, actionable execution architecture, enhancing the closed-loop remediation workflow and providing clean output hygiene.

Under the theme *“Safe, Auditable, and Automated Remediation,”* v0.5.5 introduces strict per-run folders (`RunFolder`) and leverages the Ponytail code-writing skill to apply AI-guided fixes directly to the codebase.

## 🚀 Key Features

### 1. 📂 Output Hygiene: Folder-Per-Run (`RunFolder`)
All TorusGuard operations are now isolated into a per-run folder context:
- **Base pattern:** `.torusguard/runs/run-YYYYMMDD-HHMMSS/`
- **Output segregation:**
  - `findings.md`
  - `remediation.md`
  - `recheck.md`
  - `patches/` (directory)
  - `logs/` (directory)
  - `metadata.json`

### 2. 🦄 Ponytail Integration (`/torusguard apply`)
- Direct application of remediation via the Ponytail skill.
- Produces constrained, safe, and minimal patches without rewriting large code segments.
- Strongly enforces preservation of existing validation, error handling, logging, and security boundaries.

### 3. 🔁 Closed-Loop Workflow
- Formalized `Harden ──► Apply ──► Recheck` workflow bridging AI remediation suggestions with auditable, reproducible codebase patches.

## ⚙️ Engineering & Architecture
- **RunFolder Abstraction:** Created `core/run_folder.py` to manage session state.
- **Agent Contract:** Migrated Ponytail logic directly into `SKILL.md` instructions instead of an obscure python subprocess, making the agent autonomous but highly constrained.
- **Validation Engine:** Added a new suite to `harness/runner.py` verifying `RunFolder` initialization, bringing total tests to 67. All 67 pass (100%).
