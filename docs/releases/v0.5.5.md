# Release v0.5.5 — Folder-per-Run & Ponytail Integration

**Date:** 2026-08-26  
**Release Name:** Folder-per-Run, Ponytail Integration & Remediation Safety  
**Tag:** `v0.5.5`  

---

## 🎯 Summary

TorusGuard v0.5.5 introduces a streamlined execution architecture, output hygiene, and safe closed-loop remediation workflows.

Under the theme *“Safe, Auditable, and Automated Remediation,”* v0.5.5 introduces strict per-run folders (`RunFolder`), integrates the Ponytail code-writing skill for minimal-churn patch generation, and formalizes precision calibration to prevent false alarms.

---

## 🚀 Key Features & Highlights

### 1. 📂 Output Hygiene: Folder-Per-Run (`RunFolder`)
All TorusGuard operations are segregated into an isolated per-run folder context:
- **Base pattern:** `.torusguard/runs/run-YYYYMMDD-HHMMSS/`
- **Output segregation:**
  - `findings/`
  - `evidence/`
  - `patches/`
  - `logs/`
  - `validation/`
  - `metadata.json`

### 2. 🦄 Ponytail Integration & Remediation Protocol (`/torusguard apply`)
- Direct application of remediation via the Ponytail skill.
- Produces constrained, safe, and minimal patches without rewriting large code segments.
- Enforces single-file focus, line churn limits, zero unrelated file churn, and syntax dry-run validation.

### 3. 🛡️ Rule Precision Calibration & Downgrades
- Prohibits firing `Confirmed` critical findings based solely on local line-level pattern matching when security context is managed upstream (API gateways, middleware).
- Routes ambiguous contexts to `Needs Review` to avoid audit report pollution.

### 4. 🔁 Closed-Loop Workflow
- Formalized `Harden ──► Apply ──► Recheck` workflow bridging AI security audits with reproducible codebase patches.
