## 🎯 Summary

TorusGuard v0.4.1 is a backward-compatible stabilization patch following the v0.4.0 Python platform security release. This patch refines stack detection across diverse project layouts, sharpens evidence-confidence standards, adds regression fixtures derived from authorized codebase evaluations, corrects framework-specific remediation guidance, and enhances CI release verification workflows.

---

## 🚀 Key Highlights & Improvements

### 1. 🔍 Refined Stack Detection
- Added explicit validation fixtures for Django (`manage.py`), DRF (`pyproject.toml`), FastAPI, Flask (`requirements.txt`), Flask+SQLAlchemy, pure Python libraries, and polyglot monorepos.
- Mandated structured `## Detected Stack` output including file and line evidence citations.

### 2. 🛡️ False-Positive & Evidence Hardening
- **Service-Layer Authorization (`TG-AUTH-007`):** Clarified that views delegating data lookups to domain service layers must be classified as `Manual Review` rather than false `Confirmed` vulnerabilities.
- **Serializer Mass Assignment (`TG-AUTH-006`):** Verified that explicit `read_only_fields` on privilege properties properly satisfy rule requirements.
- **Bound Parameter Searches (`TG-INPUT-003`):** Added explicit safe examples for dynamic LIKE queries in SQLAlchemy using named parameter mappings.

### 3. 🧪 Regression Fixture Suite (`tests/fixtures/python/`)
Added 10 paired safe and vulnerable regression fixtures covering:
- Django service-layer authorization vs. missing owner IDOR lookups.
- DRF read-only fields vs. unbounded pagination limits.
- FastAPI Pydantic schema boundaries vs. unvalidated outbound SSRF fetches.
- Flask CSRF protection vs. raw filename upload handling.
- SQLAlchemy parameterized queries vs. unscoped multi-tenant queries.

### 4. 🏢 Authorized Validation Framework
- Added `docs/validation/authorized-repo-validation-template.md` establishing strict legal and ethical testing boundaries (NIST / OWASP).
