# Release v0.5.0 — Architecture & Workflow Release

**Date:** 2026-08-25  
**Release Name:** Architecture & Workflow Release  
**Tag:** `v0.5.0`  

---

## 🎯 Summary

TorusGuard v0.5.0 represents a major evolutionary leap for TorusGuard, transforming it from a static rule guidance library into a structured, evidence-backed **Security Workflow Engine** for AI coding agents and developers.

Inspired by **OWASP ASVS** verification discipline and **NIST SP 800-218 (SSDF)** practices, v0.5.0 establishes a formal finding lifecycle, normalized data schemas, explicit evidence typing, and a repeatable automated validation harness.

---

## 🚀 What's New & Key Highlights

### 1. 🔄 Formal 6-Stage Finding Lifecycle
Introduces a formal state machine governing every security finding:
```text
[ Detect ] ──► [ Classify ] ──► [ Verify ] ──► [ Remediate ] ──► [ Re-check ] ──► [ Archive ]
```
- Findings must progress through explicit validation criteria before advancing to remediation.
- Post-fix differential verification via `/torusguard recheck` asserts whether a vulnerability was genuinely resolved.

### 2. 📋 Normalized Data & Evidence Schemas (`schemas/`)
Formal JSON schemas defining:
- `finding.schema.json`: Normalized finding object with rule ID, taxonomy category, severity, confidence, affected area, and standards mappings.
- `evidence.schema.json`: Explicit evidence schema with modality typing (`source`, `runtime`, `test`, `manual_review`).
- `remediation.schema.json`: Structured remediation format with problem statement, risk explanation, framework diffs, and verification steps.
- `rule.schema.json`: Schema for rule catalog metadata and frontmatter.
- `lifecycle.schema.json`: Lifecycle state transitions and constraint validations.

### 3. 🧪 Repeatable Automated Validation Harness (`harness/runner.py`)
A standalone Python validation harness executing:
- Automated schema integrity checks.
- Complete 60-rule catalog validation with 0 duplicate IDs.
- Differential verification on all vulnerable vs hardened educational pairs.
- Multi-layout stack detection fixture validation (7 layout suites).
- 10 paired Python regression fixtures.
- Lifecycle state machine transition assertions.

### 4. 🌟 Human-First Card-Style Markdown Output
Refactored report formatter (`core/formatter.py`) that produces structured, clean Markdown audit reports with traffic-light posture indicators, clear risk rationales, side-by-side Before/After diffs, and testable verification steps.

### 5. 📚 Comprehensive Workflow Documentation
- Added [`docs/architecture/v0.5.0-workflow-architecture.md`](../architecture/v0.5.0-workflow-architecture.md) detailing system architecture.
- Added [`docs/workflow/finding-lifecycle.md`](../workflow/finding-lifecycle.md) explaining finding states, evidence rules, and re-checking workflows.

## 📦 Core Commands in v0.5.0

| Command | Lifecycle Phase | Purpose |
|---------|:---:|---------|
| `/torusguard init` | Baseline | Establish threat model, `SECURITY.md`, and finding baseline |
| `/torusguard audit` | Detect & Classify | Scan codebase; produce Human-First normalized audit report |
| `/torusguard verify` | Verify | Validate evidence sufficiency and manual review criteria |
| `/torusguard harden` | Remediate | Propose least-invasive, framework-native code fixes |
| `/torusguard recheck` | Re-check | Execute differential re-audit to assert finding resolution |

## ⚖️ Technical Boundaries & Integrity

TorusGuard is an open-source Markdown-first security guidance framework for AI coding agents and human engineers. It is not an automated binary scanner, dynamic penetration testing replacement, or guarantee of 100% application security. Findings categorized as `Needs Review` require manual verification of out-of-band architecture.
