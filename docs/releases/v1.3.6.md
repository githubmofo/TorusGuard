## Wave 1: Interactive Enterprise Remediation Hub

The visual HTML report (`report.html` / `npx torusguard report --html`) now features an interactive, search-enabled remediation center powered by active learning memory:

- **Family Filter Tabs:** Instantly isolate findings by category (`All Families`, `TG-SEC`, `TG-AUTH`, `TG-DB`, `TG-INPUT`, `TG-RATE`, `TG-AGENT`, etc.) with real-time rule count badges.
- **Search Engine:** Filter Golden Recipes in real time across rule identifier, descriptive title, CWE classification, and security domain.
- **Monokai Dark Code Drawers:** High-contrast syntax highlighting for vulnerability patterns and verified fixes, with line numbering and visual language tags.
- **One-Click "Copy Golden Fix":** One-click clipboard export with animated visual confirmation badges (`Copied! ✨`).
- **Surgical Diff View:** Color-coded diff visualization verifying adherence to the Ponytail Protocol ($\le 35$ additions in green `+`, $\le 25$ deletions in red `-`).
- **Safe Exploit Simulation Canary:** Detailed proof cards with non-destructive verification tokens, targeted route endpoints, and step-by-step confirmation protocols.
- **Direct Action CLI Pills:** Instant terminal commands (`npx torusguard harden --rule <RULE_ID>`) allowing developers to execute remediation with zero manual syntax construction.

## Wave 2: 5-Layer Defended Invariants & Active Defenses Matrix

TorusGuard v1.3.6 formalizes the core security invariants protecting applications into a structured 5-layer architectural matrix:

| Invariant Layer | Primary Guardrail | Core Rules | Active Defense Mechanism |
| :--- | :--- | :--- | :--- |
| **Layer 1: Secret Zero Exposure** | Browser-Code Truth | `TG-SEC`, `TG-CLIENT` | Static AST detection of service keys, token entropy checks, bundle exclusion |
| **Layer 2: Multi-Tenant Isolation** | Scoped Access | `TG-DB` | Mandatory `tenant_id` and user ownership partitioning in all query sinks |
| **Layer 3: Ponytail Churn Bound** | Anti-Hallucination | `TG-DIFF` | Bounded surgical patches ($\le 35$ add, $\le 25$ del), zero full-file rewrites |
| **Layer 4: Sinks Sanitization** | Injection Defense | `TG-INPUT`, `TG-AGENT` | Path sanitization, shell escaping, structured LLM user-input delimiters |
| **Layer 5: Network Boundary** | SSRF Containment | `TG-SSRF`, `TG-WEBHOOK` | Private IP blocking (`169.254.169.254`), HMAC-SHA256 signature enforcement |

## Wave 3: Regulatory Compliance & Framework Mapping

To bridge the gap between AI development velocity and enterprise compliance requirements, v1.3.6 introduces automated cross-framework mapping:

- **SOC 2 Type II:**
  - **CC6.1:** Logical Access Controls (`TG-AUTH-001` to `TG-AUTH-008`, `TG-DB-001`)
  - **CC6.6:** Boundary Defense & Network Protection (`TG-SSRF-001` to `TG-SSRF-004`, `TG-WEBHOOK-001`)
  - **CC6.8:** Vulnerability Management & Threat Detection (`TG-SUPPLY-001` to `TG-SUPPLY-006`)
- **ISO/IEC 27001:2022:**
  - **A.8.20:** Network Security Controls (`TG-SSRF`, `TG-WS`)
  - **A.8.24:** Use of Cryptography (`TG-SEC`, `TG-AUTH-003`, `TG-WEBHOOK`)
  - **A.8.28:** Secure Coding Standards (`TG-INPUT`, `TG-DIFF`, `TG-AGENT`)
- **HIPAA Security Rule:**
  - **§ 164.312(a)(1):** Access Control & Multi-Tenant Separation (`TG-DB-001`, `TG-AUTH-001`)
  - **§ 164.312(c)(1):** Data Integrity & Tamper Resistance (`TG-WEBHOOK-001`, `TG-SEC-004`)
  - **§ 164.312(e)(1):** Transmission Security & TLS Enforcement (`TG-DIFF-001`, `TG-WS-001`)
- **OWASP Top 10:2025:** Direct AST detection aligned with all 10 standard vulnerability categories.
