# Release v0.5.1 — Provenance & Auditable Confidence Release

**Date:** 2026-08-25  
**Release Name:** Provenance & Auditable Confidence Release  
**Tag:** `v0.5.1`  

---

## 🎯 Summary

TorusGuard v0.5.1 refines the v0.5.0 architecture with a laser focus on **trust, precision, and reproducibility**.

Under the theme *“Normalize findings, prove provenance, and make confidence auditable,”* v0.5.1 standardizes canonical finding objects, introduces an auditable 0–100 confidence scoring rubric, tracks explicit provenance chains from discovery to verification, packages technical evidence with SHA-256 integrity checksums, and enforces strict post-remediation retest verification.

---

## 🚀 Key Highlights & Enhancements

### 1. 🔗 Structured Provenance Tracking
Every reported finding contains an immutable `provenance` record documenting:
- **Discovery Module:** The exact rule module that identified the candidate.
- **Triggering Input:** Specific AST node, configuration key, or route pattern.
- **Decision Path:** Step-by-step evaluation sequence taken by the analysis engine.
- **Verification Step:** Explicit method used to validate or refute reachability.

### 2. 📊 Auditable 0–100 Confidence Scoring Model
Replaces subjective confidence estimates with a transparent, factor-weighted 100-point rubric:
- **Evidence Quality (35 pts):** AST source proof vs regex/indirect indicators.
- **Reproduction Success (25 pts):** Deterministic reproduction in test fixtures.
- **Independent Confirmations (15 pts):** Corroboration across manifests and routes.
- **Environmental Clarity (15 pts):** Absence of ambiguous out-of-band proxy/service layers.
- **Manual Review Status (10 pts):** Validation by a human security engineer.

**Classification Bands:**
- `90–100`: **`Confirmed`**
- `70–89`: **`High Confidence`**
- `50–69`: **`Medium Confidence`**
- `< 50`: **`Needs Review` / `Unconfirmed`** (Mandatory manual review)

### 3. 📦 Cryptographic Evidence Packaging
- Extracts exact, unedited raw technical proof snippets.
- Generates a **SHA-256 cryptographic checksum** for every evidence item for audit verification.
- Strictly isolates objective **Raw Facts** from **AI Risk Interpretation**.

### 4. 🔁 Retest & Closure State Machine
- Findings can only transition to **`Verified Fixed`** after an explicit retest (`/torusguard recheck`) verifies that the safe code pattern is present and hashes the post-fix evidence.

### 5. 🧪 Repeatable Validation Harness (`harness/runner.py`)
- Standalone automated test harness running 42 validation assertions with 100% pass rate.
