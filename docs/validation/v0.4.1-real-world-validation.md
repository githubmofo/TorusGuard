## 🔍 Valid Findings (Anonymized Summary)

1. **Repo-A (Django / DRF):**
   - `TG-AUTH-006`: `UserProfileSerializer` omitted `role` from `read_only_fields`, allowing potential privilege escalation via `PUT /api/v1/profile/`.
   - `TG-RATE-001`: Custom password reset endpoint did not attach DRF `ScopedRateThrottle`.
2. **Repo-B (FastAPI):**
   - `TG-SSRF-001`: Webhook dispatcher accepted arbitrary remote URLs without checking against RFC 1918 internal IP blocks or DNS resolution rebinding.
   - `TG-AUTH-006`: Incoming user update Pydantic schema did not define `model_config = ConfigDict(extra="forbid")`.
3. **Repo-C (Flask / SQLAlchemy):**
   - `TG-INPUT-002`: Search endpoint used raw string formatting in `session.execute(f"SELECT * FROM items WHERE name LIKE '%{q}%'")`.
   - `TG-INPUT-004`: File upload handler saved incoming files using raw `file.filename` instead of Werkzeug `secure_filename()` with destination directory sandboxing.

---

## 🛡️ False Positives Identified & Resolved

- **Issue:** In Repo-A, `TG-AUTH-007` originally flagged a ViewSet endpoint because ownership checks were not found directly inside the view function.
- **Root Cause:** The codebase adhered to a clean domain-driven architecture where authorization scoping was handled inside a dedicated `OrderService.get_for_user(user_id, order_id)` service layer.
- **Resolution in v0.4.1:** Updated `TG-AUTH-007` classification standards and `SKILL.md` rules so that delegated service-layer lookups are categorized as `Manual Review` (prompting the auditor to verify the service layer) rather than flagging a false `Confirmed` vulnerability. Added regression fixture `tests/fixtures/python/django/safe-service-layer-auth/`.

## 🧪 False Negatives & Coverage Analysis

- **Edge Cases Evaluated:** Verified that multi-tenant filter chains in SQLAlchemy repositories properly trigger when tenant context is omitted from subqueries. Added regression fixture `tests/fixtures/python/sqlalchemy/missing-tenant-scope/`.

## ⚖️ Limitations & Technical Boundaries

1. **Static Guidance Framework:** TorusGuard is a Markdown-first guidance framework for AI coding agents; it does not replace dynamic penetration testing or binary runtime analysis.
2. **Contextual Boundaries:** Authorization distributed across microservice meshes or RPC gateways requires manual policy review.
3. **Third-Party Integrations:** Cloud IAM policies and database row-level security (RLS) policies configured out-of-band require independent infrastructure audits.
